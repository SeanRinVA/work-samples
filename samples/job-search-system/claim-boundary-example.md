# Claim Boundary Method (example)

Every resume bullet must be defendable in an interview. The claim boundary library records what was actually done so drafts do not drift.

## How an entry is written

- What was done (plain language)
- Scope and frequency
- What was not done
- Interview test: can this be walked through with a concrete example?

## Example entry (fictional tool)

**Area:** Backup platform administration

**What was done:** Designed the backup job configuration for a multi-server environment, installed agents on the targets, set retention and scheduling, ran regular test restores, and recovered from one failed restore by rebuilding the job and re-entering source data.

**Scope:** Single organization, several servers, weekly tests, one real recovery event. Configuration and agent deployment were owned; the underlying storage platform and multi-site design were not.

**What was not done:** Did not design or rebuild an enterprise backup architecture spanning multiple sites or a shared tape library. Did not own vendor selection or the overall storage strategy.

**Interview test:** Can walk through the job design, agent install, schedule choices, the failed restore, what the logs showed, the recovery steps, and how the process changed afterward. Cannot speak to enterprise multi-site architecture decisions or library-manager redesign.

## Rule that came out of the discussions

If the work happened once and was not repeated or owned, describe the event. Do not list the tool as a primary skill. The event is real. The specialty is not.
